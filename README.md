# 光伏卫士 PV-FireGuard

光伏电站电—热融合故障诊断与火灾预警软件模型机（中国科学技术大学 2025 年度“雏鹰基金”项目配套软件）。

> 以电—热融合为核心，实现光伏直流侧故障诊断、火灾预警与全过程事件追溯。

## 打开方式
双击 `index.html`，用 Chrome / Edge 打开即可。无需联网、无需安装，所有算法均在浏览器本地运行。

## 五大功能模块
| 模块 | 内容 | 输出 |
|---|---|---|
| ① 电站可视化与状态监测 | 建立设备与测点关联（组串 ↔ 汇流箱/MPPT ↔ CT/VT/TC/IR 测点），展示电压、电流、温度和在线状态；72 块组件阵列热-电仿真、故障注入与 5 个复杂故障场景 | 电站总览、异常分布与历史趋势 |
| ② 热异常与热斑诊断 | 分析组件、连接器等部位的热点、温差及温升过程；红外热像 → 灰度化 → 卷积特征 → 候选区域 + NMS → 分类、部位定位与分级 | 热异常位置、特征参数与待复核结果 |
| ③ 电弧故障诊断（实测数据） | 使用电弧实验平台实测数据（100 kHz，直流侧 + 交流侧电流，5 类负载 × 无弧/直流侧电弧/交流侧电弧）。先核验采样要求，再提取双通道 34 维多域特征由神经网络判别（按记录划分训练/测试），连续窗确认；支持无弧→电弧拼接回放 | 异常时段、关联回路与诊断证据 |
| ④ 电—热融合风险评估与预警 | 关联电气异常与热状态演化，依据 6 项验证判据（C1 温差、C2 温升速率、C3 故障点温度、C4 电弧特征、C5 电—热同回路关联、C6 环境加剧）分级；热失控推演与多因素风险指数作参考 | 风险等级、触发原因与处置优先级 |
| ⑤ 事件管理与诊断报告 | 事件自动建档并留存电—热证据时序；同步回放；确认 → 排查 → 处理 → 复核闭环 | 事件档案、处理状态与可导出报告（CSV / JSON / PDF） |

## 后台数据支撑层
多源数据接入与设备映射 · 时间同步与数据质量检查 · 数据预处理与特征管理 · 历史存储与事件归档 · 算法模型与预警判据管理 · 权限、日志与运行维护。
页面中可模拟测点通信中断/时钟漂移、在线修改预警判据、切换用户角色（管理员 / 运维工程师 / 只读访客），所有操作写入审计日志。

## 实测电弧数据（5-30.rar）
原始数据：29 个 CSV（约 3 GB），DAQ 采样率 100 kHz，通道0 = 交流侧电流、通道1 = 直流侧电流；
负载类型：阻性、感性、阻感、电子开关类、混合；工况：无电弧 / 直流侧电弧 / 交流侧电弧（文件名即标签）。

浏览器端无法直接读取 3 GB CSV，故先预处理为约 1.9 MB 的内嵌数据包：
1. 解析 GBK 表头与文件名标签；按 ADC 步长（≈4.93 mV）还原为 int16，近似无损；
2. 1024 点（10.24 ms）分窗，剔除无电流窗口；
3. 每条记录在 4 个位置各取 10 个连续窗（共 1160 窗），并保存每 0.1 s 的全时段统计概览；
4. 差分 + gzip + base64 编码，浏览器用 `DecompressionStream` 解压；
5. 按记录划分：序号 1 训练、序号 ≥2 测试，避免同一记录窗口泄漏到测试集。

重新生成：
```
"C:\Program Files\WinRAR\UnRAR.exe" x 5-30.rar <临时目录>\
python tools/preprocess_arc.py <临时目录>\5-30 data/arc-real.js
```
在线监测（模块①）中各组串的电流信号即从这些实测窗口回放：正常组串取同负载无弧记录，注入电弧故障时取直流侧电弧记录，逆变器干扰取电子开关类负载无弧记录。
电弧诊断页的单窗诊断与回放使用“评估模型”（只用训练集记录训练）；在线监测使用全部记录训练的“部署模型”。

## 数据接入状态
- **初始状态（尚未导入数据）为空**，各模块只在有数据或用户输入后才显示结果：
  - 电站状态监测、电弧诊断、事件与报告：显示“等待数据接入”，电站仿真不运行；
  - 热异常诊断：等待上传红外图像，或用户点击“生成并诊断”生成标注为“仿真”的热像；
  - 电—热融合评估：等待用户设置工况并点击“开始评估”，或从电站载入选中组件；
  - 数据与系统：测点显示“未接入”、质量检查显示“无数据”；设备映射、判据、权限与审计日志等配置信息照常显示。
- 数据来源只有两种：**手动导入**的 DAQ CSV（见下节），以及点击“加载示例数据”启用的**示例数据**（`data/arc-real.js`，5-30.rar 内置 29 条，可随时移除，启用状态保存在浏览器中）。页面顶部横幅标明当前数据来源。
- **重置数据**：清空全部导入记录与示例数据，并清除热异常诊断、融合评估结果，所有模块回到初始状态。
- 数据源每次变化（加载/移除示例、导入、替换、重置）时，电站监测重新开始，不同数据的历史不会混在一起。

**有数据后，导入数据中没有的部分以补充/仿真结果显示，并明确标注：**
- 电弧判别模型：导入数据缺少某类样本（无电弧/直流侧/交流侧）或没有测试集记录时，自动补充 5-30 示例数据（实测）参与训练与评估，训练信息中注明；
- 组串电流信号、实时检测回放：导入数据中没有所需类型的信号时，由 5-30 示例数据补充，标注“示例补充”；
- 热异常诊断：导入数据不含红外热像时，自动显示电站热仿真中温度最高组件的热像（标注“仿真”）；上传实拍图像或手动生成后替换；
- 电—热融合评估：未手动设置工况时，自动评估电站中风险最高（其次温度最高）的组件（标注“仿真”）；手动调整参数后即为手动评估。

组串电流信号来自上述实测记录；温度、红外热像、功率与气象仍为物理仿真，页面中以“仿真”标注。
在线监测对每个组串的电弧概率做跨周期指数平滑（α = 0.4），偶发的单周期高概率不触发疑似，持续电弧约 3 s 内确认。

## 手动导入实测数据
在“电弧诊断”页的“数据导入”卡片中，可选择 CSV 文件、整个文件夹，或直接拖入：
- 格式：DAQ 导出的 CSV（可含“采样率/通道数/通道名”表头），两列数值 = 交流侧、直流侧电流；采样率 100 kHz；时长 ≥ 0.45 s。
- 浏览器无法直接解压 `.rar`：请先解压 `5-30.rar`，再选择其中的 CSV 或整个 `5-30` 文件夹。
- 浏览器端执行与 `tools/preprocess_arc.py` 相同的处理（表头解析 → 分窗 → 剔除无电流窗 → 抽取 4×10 连续窗 → 0.1 s 概览），结果与 Python 脚本一致。
- 文件名自动识别负载类型、电弧位置（直流侧弧/交流侧弧/noarc）与序号；无法识别的记录标为“未标注”，只诊断、不参与训练。标签与用途（训练/测试/不参与）可在“已导入记录”中修改。
- 与内置记录同名的文件会替换内置记录；导入结果保存在本机浏览器（IndexedDB），刷新后保留，原始 CSV 不上传、不保存。
- 导入后默认自动重新训练模型；在线监测（模块①）随即使用新数据回放。
- **导入方式**：“追加到现有数据”（默认）或“替换现有数据”。替换时先解析全部新文件，至少一个成功后才清空原有数据，失败不会丢失现有数据。
- **重置数据**（数据导入卡片右上角）：清空全部导入记录（含浏览器中保存的副本）与示例数据、已训练模型、电站监测历史与事件档案，平台回到“等待数据接入”，之后可重新导入其他数据；审计日志保留。
- 单条记录可在“已导入记录”中删除；“清除全部导入”只清空导入记录、不影响示例数据。

后续接入实时采集时，采集端按同样格式产出记录后调用 `REAL.ingest(record)` 即可，界面、训练与监测无需改动。

## 说明
电弧诊断部分使用上述实测数据；红外热像、热平衡模型与风险评估部分仍为基于物理规律的仿真数据，判据阈值为示意值。接入 FLIR 红外热像仪等设备后，可用实测数据替换 `vision.js` 中的数据源，并在“后台数据支撑层”中完成判据验证与调整。
